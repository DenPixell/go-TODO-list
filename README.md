# go-TODO-list

Планировщик задач (TODO-лист) с бэкендом на Go и SQLite. Итоговый проект курса «Go-разработчик» (Яндекс Практикум).

## Описание проекта

Сервер хранит задачи с дедлайном, заголовком и комментарием. Задачи могут повторяться по правилу (ежедневно, ежегодно, по дням недели, по дням/месяцам) — при отметке о выполнении такая задача переносится на следующую дату, а обычная задача удаляется. Реализован REST API для добавления, получения списка, редактирования, удаления и выполнения задач, а также аутентификация по паролю.

## Выполненные задания со звёздочкой

- Полная поддержка правил повторения `NextDate` — включая `w` (дни недели) и `m` (дни/месяцы, в том числе отрицательные индексы `-1`, `-2`).
- Поиск задач в `/api/tasks` — по подстроке в заголовке/комментарии и по конкретной дате (формат `02.01.2006`).
- Определение порта через переменную окружения `TODO_PORT`.
- Определение пути к файлу БД через переменную окружения `TODO_DBFILE`.
- Аутентификация по паролю (`TODO_PASSWORD`) с использованием JWT-токена и middleware.
- Сборка проекта в Docker-образ.

## Стек

- Go 1.25
- `modernc.org/sqlite` — драйвер SQLite
- `github.com/golang-jwt/jwt/v5` — JWT-токены

## Запуск локально

```bash
go mod download
go run main.go
```

По умолчанию сервер слушает порт `7540`, файл БД `scheduler.db` создаётся в текущей директории при первом запуске.

Открыть в браузере: [http://localhost:7540/](http://localhost:7540/)

### Переменные окружения

| Переменная      | Назначение                                  | По умолчанию     |
|------------------|----------------------------------------------|-------------------|
| `TODO_PORT`      | порт веб-сервера                              | `7540`            |
| `TODO_DBFILE`    | путь к файлу базы данных                      | `scheduler.db`    |
| `TODO_PASSWORD`  | пароль для доступа к планировщику. Если не задан — аутентификация отключена | не задан |

Пример запуска с паролем и на другом порту:

```bash
TODO_PORT=7000 TODO_PASSWORD=12345 go run main.go
```

Если задан пароль, при заходе на `http://localhost:7540/` сервер потребует войти через `http://localhost:7540/login.html`.

## Запуск тестов

```bash
go test ./tests
```

Настройки тестов — в файле `tests/settings.go`:

```go
var Port = 7540              // порт, который слушает сервер
var DBFile = "../scheduler.db" // путь к файлу БД от директории tests
var FullNextDate = true      // проверка правил w и m в NextDate
var Search = true            // проверка поиска в /api/tasks
var Token = `...`            // JWT-токен для тестов защищённых запросов
```

Если сервер запущен с `TODO_PASSWORD`, для прогона тестов нужно получить токен и указать его в `Token`:

```bash
curl -X POST http://localhost:7540/api/signin -d '{"password":"12345"}'
```

Скопировать значение `token` из ответа в `tests/settings.go`. Сервер при этом должен быть запущен с тем же `TODO_PASSWORD`, что использовался при получении токена.

**Важно:** тест `TestDB` предполагает, что БД лежит в родительской директории от `tests` (значение `DBFile` по умолчанию), а `TestTasks` перед проверкой удаляет все задачи из таблицы `scheduler`.

## Запуск через Docker

Собрать образ:

```bash
docker build -t go-todo-list .
```

Запустить контейнер (база данных сохраняется на хосте в директории `./data`):

```bash
docker run -d \
-p 7540:7540 \
-e TODO_PASSWORD=12345 \
-e TODO_DBFILE=/app/data/scheduler.db \
-v $(pwd)/data:/app/data \
--name todo-list \
go-todo-list
```

Открыть в браузере: [http://localhost:7540/](http://localhost:7540/)

Если запуск без пароля — просто не указывать `-e TODO_PASSWORD=...`.

Остановить и удалить контейнер:

```bash
docker rm -f todo-list
```

## API

| Метод  | Путь              | Описание                              | Авторизация |
|--------|--------------------|-----------------------------------------|--------------|
| GET    | `/api/nextdate`     | вычислить следующую дату по правилу     | нет          |
| POST   | `/api/signin`       | вход по паролю, получение JWT-токена    | нет          |
| POST   | `/api/task`         | добавить задачу                          | да           |
| GET    | `/api/task?id=`     | получить задачу по id                    | да           |
| PUT    | `/api/task`         | изменить задачу                          | да           |
| DELETE | `/api/task?id=`     | удалить задачу                           | да           |
| GET    | `/api/tasks`        | список ближайших задач (+ `search=`)     | да           |
| POST   | `/api/task/done?id=`| отметить задачу выполненной              | да           |
